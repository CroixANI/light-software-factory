# Tasks

Each top-level task is one session and one PR, and maps 1:1 to a GitHub Sub-Issue of the Parent Issue of this change (D-73). All work is pre-spike: only `spike/followup/`, `docs/spike/`, `openspec/`. Every task writes its own `spike/followup/<dir>/` and its own `docs/spike/findings/followup-<name>.md`, so declared files do not overlap (D-38); only 4.1 touches `docs/spike/findings.md`. `spike/harness/**`, earlier `spike/<cli>/` directories, `docs/decisions.md` and `docs/architecture/**` are not touched by any task. A profile that needs a change is copied into the task's directory as a candidate. Where a result selects between options, the findings record the result and the options, and the choice stays with the owner. Each task line carries its GitHub issue (`#<issue>`) and its `blocked by:` note with issue numbers (the same dependencies are native "blocked by" links on GitHub); other mentions of tasks in the text use the task numbers. Task lines are left unticked (D-74 §5).

Common "done when" for every task: the findings file exists and states, per check, **what was measured, with which command, tool version and profile, and the outcome** (pass / fail / not shown, with the reason); log excerpts contain no credentials, tokens, request bodies or local paths; `npx openspec validate --all` passes; no file outside the declared ones changed. Mock-driven checks state that a mock shows the sandbox's effect on the CLI's tool shell and not provider acceptance of a credential.
