## 1. The gemini slot was tested on Antigravity `agy`, not on the Gemini CLI

The issue, the plan, D-63, ADR-004/005 and architecture §4/§5 name the **Gemini CLI**. The owner reported that Google no longer supports it and installed and logged in the **Antigravity CLI (`agy`)** instead; `agy` 1.5.14 in print mode was tested for the gemini slot. The Gemini CLI (0.70.0 was still installed) was **not exercised** and its support status is as the owner reported it, not verified. The file names `spike/gemini/` and `findings/gemini.md` were kept as declared. `agy` differs from the architecture's assumptions: another binary, another credential mechanism, other flags, and `--effort` exists (§4 says "effort `n/a`"). In this file "gemini slot" and "`agy`" mean the same thing. Whether `agy` takes that slot is a question for the owner (section 9, a).

### Where each condition comes from, in one list per CLI

**claude**
1. E8 open: the declared list and `--setting-sources ""` are the only control tried; a run with the files excluded from the copy was not made, and nested, case and `.claude/{rules,skills,agents,commands,hooks}` canaries were not tested. Until then the adapter must also exclude `.claude/` from the copy.
2. Pin `--settings '{"sandbox":{"enabled":false}}'`: with `enabled:true` a failed sandbox start silently degrades to an unsandboxed Bash tool.
3. S2: `base.sb` still leaks other processes' argv/environment (section 6); claude runs its tool shell in its own process group, so the candidate rule must be re-run with claude.
4. E2 not measured: setup-token lifetime unknown; a `provider probe` must detect `Not logged in` before a Step.
5. E11, `kill`: the tool shell's group as well as the CLI's, then a marker scan; the evidence that a survivor has no network is weak (the first probe did not ignore SIGPIPE; the fixed probe was not re-run).
6. `invalid_output` and `policy_violation` come from the output, not the exit code.

**codex**
1. E3 holds only with `com.apple.system.opendirectoryd.libinfo` allowed and `CODEX_CA_CERTIFICATE` set and readable; without the CA variable the CLI needs `com.apple.SecurityServer` (excluded by the plan).
2. Credential: the Step copy of `auth.json` carries a dummy `refresh_token` (departure from ADR-005's "copy as is"); the copy is not immutable (the profile denies only in-place writes); the access token (~10 days) stays readable by any tool process.
3. E8 `pass` because the declared list excludes `AGENTS*.md`, `.codex/**`, `.agents/**` (any depth) and `.mcp.json`, and `home/` is adapter-owned and empty; flags are a second layer.
4. E10: a no-shell Step cannot read `repo/` (no file-read tool).
5. E11 kill rule as for claude (tool-shell group, marker scan, no gateway port reuse), plus the helper process's group (`codex-code-mode-host`); unlike claude, a survivor was seen without network after the port closed.
6. `policy_violation` and `invalid_output` from item status and files, never from the exit code; an unsupported effort falls back silently (validate against the model list).

**agy**
1. Slot and provider id are open (section 9, a).
2. E3: loopback `network-inbound` on `localhost:*` is needed in every shape and conflicts with S3 (section 9, c).
3. Credential: a readable file; a shell-capable worker (and `read_file`) can read the refresh token, which would reach the model provider through tool results; no mitigation found except a dedicated, revocable account.
4. E8 `pass` by exclusion only; hooks and MCP configs are code-execution channels; no flag turns them off.
5. E10: only 14 tools are declared to the model and none lists a directory or searches content.
6. E11 kill rule as for claude (a survivor was seen without network after the port closed); E12: the CLI retries 429/500/503 for more than 100 s and ignores SIGALRM.
7. The builder shape needs the broad PTY rule (`/dev/ttys[0-9]+`).

### 4.1 `claude` (Claude Code 2.1.330)

**Headless command proposed in the findings** (prompt on stdin, inside the outer profile only; not yet an adapter):
`claude -p --output-format json --json-schema <schema> --model <alias> --effort <low…max> --setting-sources "" --settings '{"sandbox":{"enabled":false}}' --tools <list> --allowedTools <list> --permission-mode <mode> --add-dir <step>/io/out [--add-dir <step>/io/in] --no-session-persistence`. For quota use `--output-format stream-json --verbose` (it can be combined with `--json-schema`). The worker writing `io/out/result.json` itself was verified under reviewer-readonly (`--tools Write,Read`, no shell). Every file-writing run used `--add-dir`.

**Environment additions:** `CLAUDE_CONFIG_DIR=<step>/home/.claude`, `CLAUDE_CODE_TMPDIR=<step>/tmp` (the CLI creates `/tmp/claude-<uid>` regardless of `TMPDIR` otherwise), `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`, `DISABLE_TELEMETRY=1`, `DISABLE_ERROR_REPORTING=1`, `DISABLE_AUTOUPDATER=1`, and the credential variable below. Test-only: `ANTHROPIC_BASE_URL` (never in production: it redirects the OAuth token), `CLAUDE_CODE_MAX_RETRIES`, `API_TIMEOUT_MS`.

**Credential mechanism:** a long-lived token from `claude setup-token`. Two routes, both complete a call under the profile: **fd route** (`CLAUDE_CODE_OAUTH_TOKEN_FILE_DESCRIPTOR=3`, token piped on fd 3; a regular-file fd does not authenticate under `sandbox-exec`, a pipe does) keeps the token out of argv and the environment; **env route** (`CLAUDE_CODE_OAUTH_TOKEN`) exposes it to anything that can read the process environment (the open KERN_PROCARGS2 leak, section 6). The CLI strips the token from the Bash tool's environment (env route). Both routes depart from ADR-005's "credential file" (a `.credentials.json` mechanism exists in the binary but was not tested). Refresh: none measured (E2). The macOS Keychain login of the owner was not used.

**Mach allowlist:** empty. **Non-Mach rules:** exec and read of the CLI's `versions/` directory only; builder shape adds `shell.sb`. **Gateway allowlist:** `api.anthropic.com` (with the hygiene variables set; without them a `http-intake.logs.us5.datadoghq.com` connection appeared once).

**Own sandbox:** off by `sandbox.enabled=false` (also the default); see condition 2.

**Declared instruction/settings files (E8, open):** read by default: `CLAUDE_CONFIG_DIR/CLAUDE.md`, `CLAUDE_CONFIG_DIR/settings.json` (applied), `<repo>/CLAUDE.md`, `<repo>/CLAUDE.local.md`, nested `**/CLAUDE.md` (loaded lazily after a Read of a file in that directory), `<repo>/.mcp.json` (its server was started), `<repo>/.claude/settings.json` (ignored while the workspace is untrusted; trust lives in `<config dir>/.claude.json`, which the Step controls). `AGENTS.md` was **not** read (observed with a `CLAUDE.md` next to it). Declared list: `CLAUDE_CONFIG_DIR/{CLAUDE.md,settings.json,.claude.json}`; in the copy at any depth `**/CLAUDE.md`, `**/CLAUDE.local.md`, `**/.claude/**`, `**/.mcp.json` (the last observed only at the root); matching case-insensitive. Flag: **`--setting-sources ""`** removes every CLAUDE.md, settings file and MCP server in the run (`--restricted` also removes Bash/code tools; `--strict-mcp-config`, `--disable-slash-commands` exist). Not tested: `.claude/{rules,skills,agents,commands,hooks}`, user-level `~/.claude.json` MCP, managed settings, nested file with the flag, `.Claude/` case variant.

**Usage fields (E7):** `usage.{input_tokens, output_tokens, cache_creation_input_tokens, cache_read_input_tokens, server_tool_use.*}`, `total_cost_usd` (list price, `costBasis: "list"`, not what a subscription is billed), `modelUsage.<model>.{inputTokens, outputTokens, costUSD, contextWindow}`, `duration_ms`, `duration_api_ms`, `num_turns`, `session_id`; thinking tokens only in `output_tokens_details.thinking_tokens`. Quota only in `stream-json --verbose`: `rate_limit_event.rate_limit_info.{status, rateLimitType, resetsAt, overageStatus, unifiedWindows.{five_hour, seven_day}.{utilization, resetsAt, status}}`; the unit of `utilization` is unverified.

### 4.2 `codex` (codex-cli 0.171.0)

**Headless command proposed in the findings** (prompt on stdin):
`codex exec --json -m <model> -c model_reasoning_effort=<level> -s danger-full-access -c approval_policy="never" -c cli_auth_credentials_store="file" --skip-git-repo-check --ignore-user-config --ignore-rules -c project_doc_max_bytes=0 -c skills.include_instructions=false --disable plugins --disable remote_plugin --disable apps --disable in_app_updates --disable multi_agent -c web_search="disabled" -c analytics.enabled=false` (+ `--disable shell_tool` for a no-shell Step). Never `--trust`, `-p`, `--dangerously-bypass-hook-trust`. The effect of `--disable multi_agent` and `-c web_search="disabled"` on the tool list was not verified. Typed output: the worker writes `io/out/result.json` (shell or `apply_patch`), or `--output-schema <file in the Step> -o <file in io/out>` with a strict-mode schema (section 9, e).

**Environment additions:** `CODEX_HOME=<step>/home/.codex`, `CODEX_CA_CERTIFICATE=/private/etc/ssl/cert.pem` (with a read rule for that file). Steps start with an empty `CODEX_HOME`, so model and effort must be passed explicitly.

**Credential mechanism:** a file `$CODEX_HOME/auth.json` (`auth_mode: chatgpt`; `tokens.{id_token, access_token, refresh_token, …}`, `last_refresh`). The Step copy is mode 0400 with a **dummy `refresh_token`** (a refresh can only fail and cannot rotate a real one), plus a profile rule denying in-place writes to that one path. Measured lifetimes: access token ≈ 240 h, id token ≈ 1 h. The findings used a copy of the owner's existing login, not a separately created one. Real refresh was deliberately not run. `codex login status` is a local check (it cannot be the probe); a probe has to be a minimal real `codex exec` call against the real `CODEX_HOME`, which also needs `auth.openai.com`.

**Mach allowlist:** `com.apple.system.opendirectoryd.libinfo` only (without any rule the CLI fails to start with `Failed to synchronize managed preferences`); `cfprefsd.daemon` breaks the start; with `com.apple.SecurityServer` added the CA variable would be unnecessary (excluded by the plan). **Non-Mach rules:** read `/etc/codex/requirements.toml` (the CLI aborts if that read gives EPERM), read `/private/etc/ssl/cert.pem`; builder: exec of `/bin/zsh` (the shell tool runs `/bin/zsh -lc`) and a read rule for the `/bin/sh` trampoline or avoiding `sh`. **Gateway allowlist:** `chatgpt.com` only, **with the hygiene switches set** (without `--disable plugins/remote_plugin/apps` the asset hosts `*.oaiusercontent.com` appear; without `analytics.enabled=false`, `ab.chatgpt.com`); the probe adds `auth.openai.com`. A Step with no credential and default switches also reaches `api.openai.com`, `api.github.com`, `codeload.github.com`, `files.openai.com`.

**Own sandbox:** off by `-s danger-full-access` with `approval_policy="never"` (or `--dangerously-bypass-approvals-and-sandbox`). With the CLI sandbox on inside our profile the shell tool fails (`CreateProcess … Operation not permitted`), so a config file that turns it back on cannot escape.

**Declared instruction/settings files (E8, pass):** read by default: `CODEX_HOME/config.toml`, `CODEX_HOME/AGENTS.md` and `AGENTS.override.md` (the override shadows), repo-root `AGENTS.override.md` (shadows `AGENTS.md`; that `AGENTS.md` is loaded was seen only through model echoes in manual runs and one logged answer, and the shadowing rule is inferred from one variant), skills from `CODEX_HOME/skills`, `repo/.codex/skills` and `repo/.agents/skills`, execpolicy rules from `CODEX_HOME/rules`. Not read: `CLAUDE.md`, `CLAUDE.local.md`, `GEMINI.md`; `repo/.codex/config.toml`, `repo/.codex/rules` and a nested `src/AGENTS.md` at start were not applied (lazy loading of the nested file was not tested). `repo/.mcp.json` undetermined (exclude it). Declared list (case-insensitive): in `home/.codex/`: `config.toml`, `AGENTS.md`, `AGENTS.override.md`, `skills/**`, `rules/**`, `hooks.json`, `*.config.toml`; in the copy at any depth: `AGENTS.md`, `AGENTS.override.md`, `.codex/**`, `.agents/**`, `.mcp.json`. Flags (second layer): `--ignore-user-config --ignore-rules -c project_doc_max_bytes=0 -c skills.include_instructions=false`; a global file in `CODEX_HOME` has no flag, so `home/` stays adapter-owned and empty. Control: with the listed paths removed and an empty `home/.codex` the model context carried no canary; nothing was planted in `home/` for that control, so it does not itself show the `home/`, `src/AGENTS.md` or `.agents/` entries (those rest on the default and flag variants). Gaps: `project_doc_fallback_filenames`, extra roots, managed requirements content, `.Codex/`, hooks format (guessed).

**Usage fields (E7):** `turn.completed.usage = {input_tokens, cached_input_tokens, cache_write_input_tokens, output_tokens, reasoning_output_tokens}`; **cost `null`** (tokens only, no price field). Quota: not in `--json`; in the rollout file `home/.codex/sessions/…/rollout-*.jsonl`, event `token_count`, `rate_limits.{primary,secondary}.{used_percent, window_minutes, resets_at}` (this plan: one 30-day window; other plans may report two). It needs a persisted session, so quota and `--ephemeral` exclude each other. About 40 model calls moved `used_percent` by ≈2 points.

### 4.3 gemini slot: Antigravity `agy` 1.5.14

**Headless command proposed in the findings** (supersedes part A's):
`agy --output-format json --model <id> --settings '{"enableTerminalSandbox":false,"permissions":{"allow":[…],"deny":[…]}}' [--json-schema <file in the Step>] < prompt` — prompt on stdin **without `-p`** (`-p` takes the prompt as its value; an empty stdin without `-p` starts the TUI and fails with rc 0). Never `--sandbox` or `--mode auto`. Whether to add `--dangerously-skip-permissions` is open: with allow rules and no flag the first call no rule allows ends the whole run with `denied_actions`; a builder would need every command prefix and every redirected command line spelled out (`*` is not a wildcard); with the flag only deny rules (prefixes) filter. Effort: `--effort low…max` overrides the model-id suffix and is validated by the CLI. Typed output: the worker writes `io/out/result.json` with `write_file` (works under reviewer-readonly), or `--json-schema` (agy adds a `finish` tool; the schema reaches the model lossily: `const`, `additionalProperties`, `allOf`/`if-then` are dropped).

**Environment additions:** none specific (everything lives under `$HOME/.gemini/` and `$HOME/Library/Application Support/antigravity/`). The enterprise-gateway route `AGY_LLM_GATEWAY_*` was used only for the mock-model tests.

**Credential mechanism:** a **file token store** `$HOME/.gemini/antigravity-cli/antigravity-oauth-token` (0600 JSON, `{"token":{"access_token","token_type","refresh_token","expiry","expires_in":3599},"auth_method","id_token_email"}`), which the CLI uses automatically when `/usr/bin/security` is unavailable (log: `Failed keyring SaveToken, falling back to file`). The owner's own login lives only in the Keychain (service `gemini`, account `antigravity`) and was not copied. The credential used in the spike came from a **new login inside a sandboxed Step** (`agy acp --login`; the one-time code was piped to stdin). An unsandboxed run with an isolated `HOME` and no file is "not logged in" and opens a browser. Refresh (E2, measured): in memory per call (`oauth2.googleapis.com`), a read-only copy is enough, file hash unchanged, the stale copy kept working after two refreshes elsewhere over ~1 h; refresh-token lifetime beyond ~1 h, revocation and parallel refresh were not measured. The in-Step login was **not revoked** at Google (owner action).

**Mach allowlist:** `com.apple.trustd.agent` only (TLS certificate verification; `x509: OSStatus -26276` without it; `trustd` and `SecurityServer` alone did not help). **Non-Mach rules** (each shown necessary by removal except where noted): read `/private/etc/hosts` (+ `resolv.conf`, `nsswitch.conf`, stat of `/etc`, granted together, not tested separately); **`network-inbound` on `localhost:*`** (the in-process language server listens on two random loopback ports; `network-bind` alone is not enough); builder: exec of `/bin/zsh` and `file-read* file-write* file-ioctl` on `/dev/ptmx` and `/dev/ttys[0-9]+` (`(allow pseudo-tty)` alone does not help). **Gateway allowlist:** `daily-cloudcode-pa.googleapis.com`, `aicode.googleapis.com`, `www.googleapis.com` (an eligibility check; blocking it fails the call), `oauth2.googleapis.com`; `play.googleapis.com` (telemetry) and `lh3.googleusercontent.com` (avatar) can be denied. `generativelanguage.googleapis.com` only on the API-key route. The unsandboxed first run also contacted the CLI's auto-updater service; inside the profile it skips itself, by accident of the profile and not by a documented switch.

**Own sandbox:** `enableTerminalSandbox` defaults to `false`; pin it. `--sandbox` logged `enabling terminal sandbox` and the command still ran under our profile (whether a nested Seatbelt applied is unknown; do not pass it).

**Declared instruction/settings files (E8, pass by exclusion only):** read into the context by default: `<home>/.gemini/{GEMINI.md,AGENTS.md}`, `<repo>/{AGENTS.md,GEMINI.md}` (root; nested ones were not loaded at the depth tested), `<home>/.gemini/skills/*/SKILL.md` and `config/skills/*/SKILL.md`, `<repo>/.agents/skills/*/SKILL.md`, `<repo>/.agents/rules/*.md` only with front matter `trigger: always_on`. **Executed, not read:** `<home>/.gemini/config/mcp_config.json` and `<repo>/.agents/mcp_config.json` (an MCP server is started at startup), `<home>/.gemini/config/hooks.json` and `<repo>/.agents/hooks.json` (a `PreToolUse` hook ran). Settings: only `<home>/.gemini/antigravity-cli/settings.json` and inline `--settings` applied permission rules. Not read or run: `CLAUDE.md`, `CLAUDE.local.md`, `.claude/`, `repo/.gemini/**`, `repo/.mcp.json`. **No flag ignores any of these.** Declared list (case-insensitive): in `home/.gemini/`: `GEMINI.md`, `AGENTS.md`, `settings.json`, `skills/**`, `antigravity-cli/{settings.json,hooks.json}`, `config/{config.json,mcp_config.json,hooks.json,skills/**,workflows/**,plugins/**,rules*,skills.json}` (agy writes `config/{config.json,mcp_config.json,projects/}` itself on first start, so `home/` must be adapter-owned and otherwise empty; keep `$HOME/Library/Application Support/antigravity/` in the list); in the copy at any depth: `AGENTS.md`, `GEMINI.md`, `.agents/**`, `.gemini/**`, plus the other adapters' `CLAUDE*.md`, `.claude/**`, `.codex/**`, `.mcp.json`. Pin `--settings` inline, never a file. Control: with the paths removed and an empty `home/.gemini` the first two requests carried no canary and no marker file appeared. The real model **acted on** the planted `AGENTS.md`/`GEMINI.md` (their canary appeared in its answer and in `notes`), so an instruction file in the copy is an injection channel. Gaps: `plugins/`, `skills.json`/`rules.json`, case variants, nested loading at other depths, managed settings, hook/MCP formats guessed from the binary.

**Usage fields (E7):** `usage = {input_tokens, output_tokens, thinking_tokens, cache_read_tokens, total_tokens}` (mapping measured with the mock: input = prompt − cached, output = candidates + thoughts); **cost `null`** (no price field). ## 5. Failure patterns (E12) and the ADR-004 closed list

ADR-004's classes: `timeout`, `rate_limited`, `provider_unavailable`, `invalid_output`, `policy_violation`, `crashed`, `cancelled`. All three CLIs were forced with a **mock API** (HTTP statuses, hangs) and with their own conditions; a real **quota** 429 could not be forced for any of them, so how a quota refusal differs from a burst refusal is not shown for claude and agy (codex's mock body `usage_limit_reached` was distinguishable in text only). None of the three has an `auth` class; a 401 or an expired credential must be caught by a probe before a Step.

### Questions for the owner (open; no answer is assumed)

**(a) The gemini slot and `agy`.** `agy` instead of the Gemini CLI in D-63, ADR-004/005, §4 and §5; the provider id (`gemini` or another); and whether the three `supported (conditional)` verdicts are accepted as **conditions of the adapter and of `doctor`** (section 2) rather than as passed checks. The Gemini CLI itself was not exercised.

**(b) Dummy refresh token and an immutable credential copy.** codex's copy carries a dummy `refresh_token` (a Step can never rotate the real one): a departure from ADR-005's "copy as is". Making any copy really immutable is unsolved: codex's profile rule denies in-place writes to one path, a worker can still rename `home/.codex`, and the CLI needs `CODEX_HOME` writable for its own state; agy's read-only copy denies writes and appends (S4) but not reads. The residual exposure is reading: codex's access token (~10 days) and agy's refresh token reach the model provider if a shell-capable worker reads and prints them; claude's fd route keeps its token out of the Step but the env route is exposed to the open process-info leak. With D-75 (proposed) the credential is a separate sign-in in a factory directory, so for codex the refresh token is no longer shared with the owner's own app (inference, not measured), which changes the risk the dummy was meant to remove; D-75 leaves the dummy open.

**(c) agy's loopback listen rule against S3.** `network-inbound` on `localhost:*` is needed in **every** role: the in-process language server listens on random loopback ports. S3 says a worker cannot be a local server; with this rule a worker (and, in the builder shape, its shell tools) can squat a port the orchestrator later hands to another Step's gateway, and receive that Step's proxied CONNECTs or block its gateway. It is worse than part A recorded: `ANTIGRAVITY_CSRF_TOKEN` and `ANTIGRAVITY_LS_ADDRESS` are visible in the tool shell's environment. `dotnet test` (VSTest) needs the same kind of rule (S5). Mitigations named in the findings, **none tested**: never reuse or pre-announce gateway ports; bind the gateway port before the worker starts; kill the whole tool-shell group; per-process narrowing is not expressible. Options for the owner: start the gateway before the worker, never reuse ports, kill the group, and bind gateways on port 0 (this last one is a suggestion made while consolidating, not tested), or accept the risk. The builder shape also needs the broad PTY rule `/dev/ttys[0-9]+`, which matches every pseudo-terminal of the machine, including the owner's terminals (a worker could read keystrokes from or write escape sequences into them); it cannot be narrowed because a Step does not know its ttys in advance.

Hooks and MCP configs are code-execution channels (claude `.mcp.json`, agy `hooks.json`/`mcp_config.json`; codex hooks unconfirmed). Proposal for §5, for the owner to accept or reject: define E8 as "exclusion of the declared paths at any depth, case-insensitive, plus an adapter-owned empty `home/`", with flags as a second layer, and re-grade claude by running its exclusion control.

**(e) ADR-004: may the adapter write `io/out/result.json` from the CLI's structured output?** claude's `structured_output` and codex's `--output-schema` + `-o` (a strict-mode schema derived from the envelope; the harness must drop nulls and keep the conditional `needs_context` rule as its own check) and agy's `--json-schema` (a lossy schema) all produce a typed object that the harness could materialise. ADR-004 as written has the worker write the file, which works for all three CLIs including without a shell. The question is whether the second route is allowed at all.

**(f) Exit criterion 4 is open for all three CLIs.** Section 8 lists what is left. claude additionally has E8 (open), S2 (candidate rule to re-run with claude) and E11 (survivor-network evidence weak) unresolved. ## 10. Notes for #21 (architecture proposals)

Minor items, not decisions:

- **`agy` retries 429/500/503 for more than 100 s** (7 attempts) and **ignores SIGALRM**: the orchestrator needs its own timeout with TERM then KILL after 10 s; `perl -e 'alarm N; exec …'` does not stop it. A TERM gets a structured JSON result. (claude's alarm reaches the CLI only because `run-claude.sh` now `exec`s `sandbox-exec`.)

- **Silent effort fallback:** codex falls back to `medium` for an unsupported effort without an error; validate effort against the model list. agy rejects it before any request.
- Other items from the findings that the §4/§5 text should absorb: gateways bind `127.0.0.1` and configuration uses literal IPs (S3); per-Step kill = tool-shell group + helper group + marker scan, never reuse gateway ports (E11, all three); discard a worker-touched Step by deleting and rebuilding it fresh with an empty `home/`, not by running `git` in it (E9); `home/` is adapter-owned and empty, transcripts persist there otherwise (E9); gateway allowlists per CLI (section 4); a Step folder must not be shaped like a Claude session scratchpad (the CLI then refuses to load instruction files and an E8 test proves nothing); `NODEROOT` read access covers the whole node prefix, possibly a registry token (claude.md notes); worker stdout/stderr as pipes or Step files (S5); `bin/obj` in `repo/` count as diff-check changes (S5).
