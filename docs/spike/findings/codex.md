# codex, part A: E1–E5 (task 3.3, issue #16)

Evidence: [spike/codex/](../../../spike/codex/) (`run-codex.sh`, `codex.sb`, `shell.sb`, `part-a.sh`, `logs-part-a.txt`). Plan: [../plan.md](../plan.md). Part B (E6–E12, S1–S5 re-run) is task 3.4 (issue #17) and is appended to this file.

**Evidence levels.** "Log" = one row of [logs-part-a.txt](../../../spike/codex/logs-part-a.txt), produced by `part-a.sh` (one run per row, so a single observation; the extended script was executed twice with the same outcomes, only the last output is kept). "Manual" = an earlier interactive run whose output was not kept; it is marked as such and is not counted as evidence.

## Setup
- macOS 27.2.1 (arm64); codex-cli 0.171.0 (native Mach-O binary in `~/.codex/packages/standalone/releases/0.171.0-aarch64-apple-darwin/bin/`, symlinked from `~/.local/bin/codex`; the launcher resolves it and grants read + exec on that `bin/` directory only; nothing else of the install was needed).
- Credential: the owner's ChatGPT login, a **file** `$CODEX_HOME/auth.json` (`auth_mode: chatgpt`; fields `tokens.{id_token, access_token, refresh_token, oauth_provenance, login_owner_id, account_id}`, `last_refresh`; ~4 KB). `lib.sh step` installs a mode 0400 copy at `<step>/home/.codex/auth.json` **with the refresh token replaced by a dummy** (`mutate-auth.py dummy-refresh`); `codex.sb` denies `file-write*` on that one path (against in-place writes only: the home write rule would still let a worker rename `home/.codex` and rewrite the file; denying all writes under `home/.codex` is not possible because the CLI keeps its state there, and the credential must sit in `CODEX_HOME`, so a mechanism that really makes the copy immutable is an open question for the owner). Never printed or committed; `part-a.sh` removes all Step folders (and so the copies) on exit. **Exception:** the earlier manual runs (first E1/E3/E4/E5 exploration and the bisects) used an unmodified copy including the owner's real refresh token, and the shell-tool runs among them had an allow-all gateway: a worker could have read and sent it. The E5 runs in `part-a.sh` use a gateway that allows only `chatgpt.com`, still with a readable access token (see E2); the E1–E4 gateways are allow-all, but in those runs the profile allows no exec besides the CLI, so there is no way for a worker to read the file. No such request was made, the copies were deleted afterwards, and no refresh was triggered, but this is the exposure E2 below is about.
- Step folder from `build-step-folder.sh` (it clones `spike/harness/sample-repo/`, which **already contains planted `AGENTS.md`, `CLAUDE.md`, `.codex/config.toml` (the text `PLANTED-CODEX-CONFIG`, not valid TOML) and others**, so no part-A run used a clean repository), a gateway from `connect-proxy.mjs --port <p>` (one per run for the E1–E4 rows, for a clean host list; the five E5 shell-tool runs share one gateway that only allows `chatgpt.com`, so no host counts are taken from them). Profile: `base.sb` + `codex.sb` (+ `shell.sb` for shell-tool runs) + one `mach-lookup` rule: `com.apple.system.opendirectoryd.libinfo` (see E3).
- Environment (empty + allowlist): `PATH=/usr/bin:/bin`, `HOME=<step>/home`, `CODEX_HOME=<step>/home/.codex`, `TMPDIR=<step>/tmp`, `LANG`, `TERM=dumb`, `HTTP(S)_PROXY=http://127.0.0.1:<port>`, `FACTORY_STEP`, **`CODEX_CA_CERTIFICATE=/private/etc/ssl/cert.pem`** (E3: needed to avoid the Keychain daemon).
- Prompt on stdin. Base command (`R=spike/codex/run-codex.sh`, `S` = step folder, `perl -e 'alarm 90; exec @ARGV'` as wall clock, macOS has no `timeout`):
  `$R --step $S --port 8941 --env CODEX_CA_CERTIFICATE=/private/etc/ssl/cert.pem --mach com.apple.system.opendirectoryd.libinfo -- exec --json --skip-git-repo-check -s read-only [-c 'cli_auth_credentials_store="file"']`
- `SP=<NEW scratch dir outside the repo> spike/codex/part-a.sh` (it refuses an existing directory it did not create, and deletes `$SP/work` on exit) runs every row below that says "log" with fresh Steps, including the E2 mutated-credential runs (`mutate-auth.py`, modes `old-last-refresh`, `bad-access-token`; `show-exp` prints token lifetimes without token values).

Claude's fd route keeps its token out of the Step; nothing equivalent was found for codex (the credential is read from `CODEX_HOME/auth.json`). **Open (part B / owner):** what the probe command is (`codex login status` prints `Logged in using ChatGPT`; whether it validates against the server was not checked), whether a refresh rotates the refresh token, and what happens to the owner's Codex app when its `auth.json` is rewritten. |

## Other findings
- **Repository instructions are read:** in several manual E5 runs (output not kept) the model volunteered the planted `AGENTS.md` canary (`CANARY-AGENTS-MD`) although the prompt did not ask for it; the final log run did not echo it (model-dependent), so this is an observation, not a measurement. This is E8 (part B); noted here because it affects every Step: the adapter must exclude instruction files from the copy or find a flag.
- `home/.codex/` after a run holds `sessions/`, `state_5.sqlite*`, `logs_2.sqlite*`, `goals_1.sqlite*`, `memories_1.sqlite`, `queue_1.sqlite*`, `thread_history_1.sqlite`, `models_cache.json` (~177 KB, fetched over the gateway), `installation_id`, `plugins/`, `skills/`, `cache/` (manual listing). State carries over only through `home/` (E9, part B; `--ephemeral` exists).
- With `--json` stdout is JSONL events (`thread.started`, `turn.started`, `item.completed`, `turn.completed` with `usage.{input_tokens, cached_input_tokens, output_tokens, reasoning_output_tokens}`); a one-word answer used ~13 000 input tokens (10 752 cached) in the manual runs. E6/E7 are part B.
- Steps start with an empty `CODEX_HOME`, so the adapter must pass model and effort itself (the CLI reads them from `config.toml` otherwise; E6, part B).
- zsh note for harness authors: `$RANDOM`/counters changed inside `$(…)` do not persist (a first set of manual runs silently reused one Step folder); use a unique id per run.

## Verdict for part A
E1, E3 (for the CLI itself), E4, E5 pass for `codex`; E2 recorded, with the real refresh deliberately not run. No `unsupported` condition of D-63 is met. **Condition:** E3 passes only with `CODEX_CA_CERTIFICATE` set and readable and `libinfo` allowed; if either is dropped the CLI needs the Keychain daemon (`SecurityServer`) and E3 fails. The final verdict waits for part B (#17).

## Proposed effect on the architecture (for task 4.2; `decisions.md` is not edited here)
- §4 Fit table, codex: headless = `codex exec --json -s danger-full-access -c approval_policy="never" -c cli_auth_credentials_store="file" --skip-git-repo-check --disable plugins --disable remote_plugin --disable apps --disable in_app_updates -c analytics.enabled=false`, prompt on stdin (model/effort/schema flags: part B); credential = the owner's ChatGPT `auth.json` copied read-only into `<step>/home/.codex` **with a dummy `refresh_token`** (a departure from "copy the file as is" in ADR-005; needs the owner's decision); refresh = probe only, ~10-day access token; residual exposure of the access token to the worker (see E2) needs the owner's decision.
- §5: Mach allowlist for codex = `com.apple.system.opendirectoryd.libinfo` only (Keychain stays excluded because the CA bundle is supplied); env allowlist additions `CODEX_HOME`, `CODEX_CA_CERTIFICATE`; read rules for `/etc/codex/requirements.toml` and `/etc/ssl/cert.pem`; exec rule for `/bin/zsh` in the builder shape; gateway allowlist = `chatgpt.com` (+ `auth.openai.com` for the probe).
- ADR-005: the credential is a file, so this CLI fits the ADR text better than claude's token-in-env route; the dummy-refresh-token change is the only departure.
