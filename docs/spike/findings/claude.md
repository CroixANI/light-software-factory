# claude, part A: E1–E5 (task 3.1, issue #14)

Evidence: [spike/claude/](../../../spike/claude/) (`run-claude.sh`, `claude.sb`, `shell.sb`). Plan: [../plan.md](../plan.md). Part B (E6–E12, S1–S5 re-run) is task 3.2 (issue #15), recorded at the end of this file.

## Setup
- macOS 27.2.1 (arm64); Claude Code 2.1.330 (native Mach-O binary in `~/.local/share/claude/versions/`, symlinked from `~/.local/bin/claude`; the launcher resolves it and grants read + exec on that `versions/` directory only).
- Credential: a long-lived token from `claude setup-token` (owner login), stored in a 0600 file outside the repo, read by the launcher and handed to the CLI in one of two ways: **fd route (launcher default)**: the file is piped to the CLI on fd 3 and `CLAUDE_CODE_OAUTH_TOKEN_FILE_DESCRIPTOR=3` is set, so the token is in neither argv nor the environment; **env route (`--env-token`)**: `CLAUDE_CODE_OAUTH_TOKEN`, visible in the argv of `/usr/bin/env` until it execs `sandbox-exec`. Never printed or committed. The runs below used the env route; the fd route was run afterwards (review round 1) and also completes a call under the profile (`is_error=false`). A **regular-file** fd (`3<file`) did not authenticate under `sandbox-exec` (`Not logged in`) although it works unsandboxed; a **pipe** (`3< <(cat file)`) works.
- Step folder from `build-step-folder.sh`, a gateway from `connect-proxy.mjs --port 8911` (allow all, to see every host). Profile: `base.sb` + `claude.sb` (exec of the CLI dir). **No Mach rule at all.**
- Environment (empty + allowlist): `PATH=/usr/bin:/bin`, `HOME=<step>/home`, `CLAUDE_CONFIG_DIR=<step>/home/.claude`, `TMPDIR` and `CLAUDE_CODE_TMPDIR=<step>/tmp`, `LANG`, `TERM=dumb`, `HTTP(S)_PROXY=http://127.0.0.1:<port>`, `FACTORY_STEP`, `CLAUDE_CODE_OAUTH_TOKEN` or `..._FILE_DESCRIPTOR`, and the hygiene switches `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1 DISABLE_TELEMETRY=1 DISABLE_ERROR_REPORTING=1 DISABLE_AUTOUPDATER=1`.

Commands (prompt on stdin; `R=spike/claude/run-claude.sh`; `S` = step folder; gateway on 8911; the 60 s limit was a wrapper such as `perl -e 'alarm 60; exec @ARGV'`, macOS has no `timeout`):
- E1 unsandboxed baseline: `/usr/bin/env -i PATH=/usr/bin:/bin HOME=$S/home CLAUDE_CONFIG_DIR=$S/home/.claude TMPDIR=$S/tmp TERM=dumb CLAUDE_CODE_OAUTH_TOKEN=<from file> <claude> -p --output-format json`
- E1 sandboxed: `$R --step $S --port 8911 -- -p --output-format json` (`--env-token` for the env route); without credential: add `--no-token`
- E4 dead port: `$R --step $S --port 8999 -- -p --output-format json` (killed by the 60 s wrapper, rc 124)
- E5: `$R --step $S --port 8911 --extra-sb spike/claude/shell.sb -- -p --output-format json --permission-mode bypassPermissions --allowedTools Bash --debug-file $S/home/dbg.txt --settings '{"sandbox":{"enabled":true|false}}'`, prompt "use the Bash tool to run `echo hello-from-bash`"; a second prompt prints whether `$CLAUDE_CODE_OAUTH_TOKEN` is set in the tool shell.

## Other findings
- **`/tmp/claude-<uid>` is created regardless of `TMPDIR`** (first run: `EPERM: mkdir '/tmp/claude-<uid>'`). `CLAUDE_CODE_TMPDIR=<step>/tmp` redirects it (it then creates `<step>/tmp/claude-<uid>`). Needs to be in the env allowlist; no profile rule for `/tmp` is needed.
- **The token is not visible to the Bash tool** (env route) (`[ -n "$CLAUDE_CODE_OAUTH_TOKEN" ]` is false inside a tool call, with and without its sandbox): the CLI strips it from child environments. The token is visible to the CLI process itself and to anything that can read its environment (open KERN_PROCARGS2 leak, [sandbox-s1-s2.md](sandbox-s1-s2.md): with the env route another same-owner process, including a sandboxed worker of another Step, can read this long-lived token from the CLI's environment). The fd route keeps it out of argv and the environment and is the better candidate. ADR-005 describes a read-only credential **file** in the Step, so an fd/env token departs from it and needs a proposed `D-` entry from the owner; none was written here.
- The sample repo's planted `CLAUDE.md` / `CLAUDE.local.md` were **read** by the CLI in both runs (their canary strings were echoed back in the E5 runs, sandbox setting on and off); `.claude/settings.json` `permissions.allow` was reported as ignored because the workspace is untrusted. This is E8 (part B), noted here only because it affects every Step: instruction files must be excluded from the copy or ignored by flag.
- `duration_api_ms` ~0.8–7 s for a one-word answer; cost ~0.03 USD per call with the default model (E7 is part B).

## Verdict for part A (superseded by the final verdict below)
E1, E3, E4, E5 pass for `claude` with the token route; E2 recorded as not measured. No part-A condition for `unsupported` was met. Final verdict waits for part B (#15).

## Proposed effect on the architecture (for task 4.2)
- §4 Fit table, claude: credential = token from `claude setup-token` (owner login, no Keychain), preferably via `CLAUDE_CODE_OAUTH_TOKEN_FILE_DESCRIPTOR` (pipe) rather than `CLAUDE_CODE_OAUTH_TOKEN` (needs a `D-` entry; ADR-005 says credential file); refresh = none (long-lived, expiry unknown).
- §5: Mach allowlist for claude = empty; env allowlist additions `CLAUDE_CODE_TMPDIR`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`, `DISABLE_TELEMETRY`, `DISABLE_ERROR_REPORTING`, `DISABLE_AUTOUPDATER`; gateway allowlist = `api.anthropic.com`; own sandbox off via `sandbox.enabled=false`.

# claude, part B: E6–E12, S1–S5 re-run (task 3.2, issue #15)

Evidence: [spike/claude/](../../../spike/claude/) (`run-claude.sh` now also takes `--env K=V` and `--node-root DIR`; `part-b-lib.sh`, `e11-spawn.sh`, `e11-kill.sh`, `kill.sb`, `s1s5.sh`, `s5.sb`, `mock-api.mjs`). Same setup as part A (Claude Code 2.1.330, macOS 27.2.1, fd-route token, gateway `connect-proxy.mjs --port 8911`, step folders from `build-step-folder.sh`, `claude.sb`, empty Mach list). Common flags below: `$FL0` = `-p --output-format json --model haiku --setting-sources ""`; prompt on stdin; every run had a wall-clock limit (`perl -e 'alarm 120; exec @ARGV'`).

The first E8 runs were invalid for that reason and were redone under a neutral temp directory. A Step folder must not be shaped like that, or an instruction-file test proves nothing.

## Other findings (part B)
- `Failed to read OAuth token from file descriptor 3: EPERM … open '/dev/fd/3'` is logged at `[ERROR]` in the debug file, followed by `Successfully read OAuth token directly from inherited descriptor 3`: harmless, the profile blocks reopening `/dev/fd/N`, the CLI falls back to the inherited fd. The fd route works.
- With `--setting-sources ""` and the hygiene variables the debug log still shows a `Remote settings` fetch (404) and `policy-limits` files written to `home/.claude/`: these go through the gateway to `api.anthropic.com`.
- Subagent/other-model behaviour was not explored; `--model haiku` was used throughout to keep cost low (≈0.001–0.005 USD per call; the whole part B cost well under 0.2 USD on the list basis).
- zsh note for the adapter authors: an unquoted `$flags` string is not word-split in zsh; the first `--setting-sources user` runs failed with rc 1 for that reason. Pass arrays.

## Final verdict (parts A + B): `supported`
E1, E3, E4, E5, E6, E8, E10, E11 pass; E2, E7 (quota unit), E9, E12 recorded, with the conditions: E2 not measured (setup-token lifetime unknown, owner/`provider probe`); `--setting-sources ""` and `sandbox.enabled=false` pinned; kill procedure includes the tool shell's group and the marker scan; `sandbox_denied` and invalid output are detected by the harness, not by exit code. ## Proposed effect on the architecture (for task 4.2)
- §4 Fit table: claude headless = `claude -p --output-format json --json-schema <schema> --model <alias> --effort <level> --setting-sources "" --tools <list> --allowedTools <list> --permission-mode <mode> --no-session-persistence`, prompt on stdin; typed output in `structured_output`; usage in `usage`/`modelUsage`/`total_cost_usd`; quota via `stream-json` `rate_limit_event`.
